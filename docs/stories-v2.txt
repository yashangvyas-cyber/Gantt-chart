## Common rules
 Read these once. The stories do not repeat them.
 Rule What it means
 Access To read the Gantt: Task management → View. To change dates, link issues, save a baseline or create a client link: Task management → Edit (Project Management → Config → Access Levels). 
 Where it lives Side Navigation bar → Tasks → <project> → Board → Gantt. Or Projects → <project> → Task Boards → View Task Board → Gantt. Every story starts here unless it says otherwise. The user is logged in with a registered Email ID and Password. 
 NEW One toolbar All Gantt controls sit in one toolbar, left to right: Sprint, Group by, Type | Week, Month, Quarter, Today | Baseline, Unscheduled | Share. Active filters show as chips with one “Clear all”. 
 Bar colour The bar takes the colour of its status column on the board: To Do #2B83DE, In Progress #F7A23A, In Review #E23333, Ready For QA #7EC451, Closed #696969. 
 NEW One hover card Point at any bar to see: status, Start Date, Due Date, Logged Time against Estimated Time, and the saved baseline dates when the baseline is on. 
 Date changes Every Start Date or Due Date change (form, panel, drag, drop) adds a History entry: “<user name> updated Start Date to <date>”. Watchers are told through “Other changes (title, description, priority, etc.)” in Notification Settings. 
 NEW Undo After a drag or drop, a toast says “Dates updated” with an Undo link for 10 seconds. 
 Dates Calendar days, DD-MMM-YYYY. “Today” is the viewer’s local date. Start Date must be on or before Due Date, or nothing is saved. Messages: “Start Date should be on or before Due Date.” and “Due Date should be on or after Start Date.”

## Add a Start Date to an issue
 Role Project Manager 
 Goal to set a Start Date on an issue 
 Benefit every issue has a clear place on the schedule 
### Simple Example se samjho: Yeh kyun chahiye?
 Maan lo: Client ne ek bada feature diya — "Payment Gateway Integration" jo 20-Nov ko deliver karna hai aur dev team ko karne me 4 din lagenge.
 1. Purani Problem: Aaj ke CollabCRM me sirf Due Date (20-Nov) hoti hai. Developer ko kab shuru karna hai kisi ko pata nahi hota, to developer aakhri din (19 ya 20 ko) kaam shuru karta hai aur deliver late ho jata hai.
 2. Asli Kaam (Solution): Nayi issue banate waqt pop-up modal me Sprint ke theek neeche Start Date (17-Nov) aur Due Date (20-Nov) dono side-by-side select karenge. Form save hote hi developer aur PM dono ko saaf pata hai ki kaam 17 ko start hona hai, 20 ko nahi.
 Waise sach bolun Sir, to bina Start Date ke Gantt ban hi nahi sakta, kyunki calendar pe bar kahan se shuru hogi wo Start Date hi decide karti hai.
 Who uses it
 Project Manager Team Member Delivery Head 
 What it touches
 Issue form and panel Issue History Notification Settings Roles and Access Levels 
 Needs
Edit access. A project with a task board. Common rules apply.

 6 Go to Side Navigation bar → Tasks → <project> → Issue List. Click “Create Issue”.
 NEW The drawer shows Start Date and Due Date side by side, under Sprint. The other fields stay as today:
 Title Description Assignee Reporter Issue Type Priority Sprint Estimated Time 
 Enter the Title. Pick the Issue Type:
 Epic Story Task Bug 
 Pick a Start Date and a Due Date. Click “Create”.
 NEW Open the issue. The right-side panel shows Start Date next to Due Date.
 NEW Click Start Date in the panel and pick a new day. It saves at once and the History tab logs it.
### Fields
 2 Field Type Required Format Error message
 Start Date Date Optional Date picker, placeholder “Select Date”, DD-MMM-YYYY, for example 30-Nov-2026. NEW “Start Date should be on or before Due Date.” 
 Due Date Date Optional Same picker and format. NEW “Due Date should be on or after Start Date.” 
### Rules to check
 3 Start Date must be on or before Due Date. If not, the issue is not saved.
 Start Date can stay blank. With no Start Date and no sprint, the issue goes to the Unscheduled list.
 Every change is logged and watchers are told (see Common rules).
 When it is done
The issue is saved with valid dates. They show in the panel, the Issue List and the Gantt.

## Read the plan on the Gantt
 Role Project Manager 
 Goal a Gantt tab on the task board 
 Benefit I can read the plan on a calendar, narrow it to the work I review and zoom to the scale I need 
### Simple Example se samjho: Yeh kyun chahiye?
 Maan lo: Sprint me 40 alag-alag tasks chal rahe hain aur client puchta hai "aaj hum kahan khade hain aur agle hafte kya deliver hoga?"

 2. Asli Kaam (Solution): PM Tasks me Gantt tab kholta hai. Har task calendar ke dates par colored strip (bar) ban ke dikhta hai. Beech me vertical blue Today Line khadi hoti hai jo batati hai ki aaj ki date tak kitna kaam complete ho jana chahiye tha. Bar pe mouse le jaate hi Logged vs Estimated time aur dates ka clean card pop-up ho jata hai.
 Waise sach bolun Sir, to isse PM ko daily standup me har developer se puchna nahi padta ki kab shuru kiya aur kab khatam karoge — screen kholte hi saaf dikh jata hai.

## See hours, milestones and sprints on top
 Role Delivery Head 
 Goal project hours, milestones and sprints above the issue rows 
 Benefit I can judge plan and spend while I read the schedule 
### Simple Example se samjho: Yeh kyun chahiye?
 Maan lo: Aap teen alag models pe projects deliver kar rahe ho — Fixed Cost, Hourly, aur Hire Base.
 1. Fixed Cost Project: Client se payment milestone pe milni hai. Top pe Milestones row (M1, M2, M3) pinned rehti hai taaki tasks schedule karte waqt milestone date miss na ho.
 2. Hourly Project: Client ne 500 hours purchase kiye hain. Top pe strip saaf batati hai: Purchased: 500h | Billed: 250h | Spent: 220h | Balance: 280h aur contract ki Expiry Date line. Agar balance khatam hone lage ya expiry pass aaye, to PM ko turant alert mil jata hai ki client se top-up mangna hai. (Yahan milestones nahi hote).
 3. Hire Base Project: Monthly dedicated developer ka contract hai. Top pe contract start, end aur remaining days dikhte hain (milestones yahan bhi nahi hote).
 Waise sach bolun Sir, to project manager ko ghanta fark nahi padta report me kya hai agar chart ke theek upar live hours aur milestones nahi dikhein.
 Who uses it
 Delivery Head Project Manager Client Team Member 
 What it touches
 Fixed Cost Report Hourly Report Hirebase Report Work Log and Billing Project Milestones tab Backlog and sprints 
 Needs
View access. Milestones added under Projects → <project> → Milestones. Sprint dates set in the Backlog. Common rules apply.

 Point at a bar to see Logged Time against Estimated Time (from Time Tracking and My Work Log).
 Open Fixed Cost Report, Hourly Report or Hirebase Report. The values match the header.

 Completing a sprint moves open issues as the board does today. Their bars follow.
 When it is done
Hours, milestones and sprints show in pinned top rows with the right colours and dates. Issue bars line up with them.

## Change dates from the Gantt
 Role Project Manager 
 Goal to drag bars and drop undated issues on the chart 
 Benefit I can schedule work without opening the issue panel 
### Simple Example se samjho: Yeh kyun chahiye?
 Maan lo: Client ka call aaya ki "Diwali offer campaign 3 din late start karo aur delivery date bhi 3 din aage badha do".
 1. Purani Problem: PM ko har task ka detail drawer kholna padta tha, Start Date edit karke save karo, Due Date edit karke save karo — 10 tasks ke liye 20 baar click karo.
 2. Asli Kaam (Drag & Drop): Gantt pe task bar ko mouse se pakad kar 3 din aage drag kar diya — Start Date aur Due Date dono ek sath shift ho gayi. Agar sirf duration badhani hai, to bar ke right edge ko pakad kar stretch kar do. Agar galti se move ho gaya, to turant bottom toast pe Undo daba do.
 3. Unscheduled Drawer: Jin tasks ki date nahi dali, wo right-side Unscheduled drawer me baithe hote hain. Wahan se direct pakad ke calendar pe drop kiya aur task schedule ho gaya.
 Waise sach bolun Sir, to Gantt ka 80% maza isi drag & drop me hai, varna Excel sheet me aur Gantt me koi fark nahi rehta.
 Who uses it
 Project Manager Team Member 
 What it touches
 Issue form and panel Issue History Notification Settings Backlog and sprints Roles and Access Levels 
 Needs
Edit access. Common rules apply. 
 [IMG] Drag a bar to change its dates. Click to enlarge [IMG] The Unscheduled button in the toolbar. Click to enlarge 
### Steps
 8 NEW Drag the body of a bar. Start Date and Due Date move by the same number of days.
 NEW Drag the left edge to change Start Date. Drag the right edge to change Due Date.
 Release. Both dates save and an Undo toast shows. Open the issue panel and History tab to see the change.
 NEW Click “Unscheduled” in the toolbar. It shows the count of issues with no dates and opens a side panel. Search by Key or Title.
 NEW Drag an issue from the panel onto an empty spot on the calendar. Start Date and Due Date follow the drop position. A solid bar appears and the count falls by one.
 NEW No dragging? Click the issue in the panel and pick dates in a date picker. The result is the same.
 NEW Or choose a Sprint in the issue panel. A light bar spans that sprint’s Start Date to End Date.
 A teammate with View access opens the same Gantt and sees the new dates. The drag control stays hidden.
### Fields
 3 Field Type Required Format Error message
 Start Date Date Optional Calendar days, DD-MMM-YYYY. Set by the drop position. NEW “Start Date should be on or before Due Date.” 
 Due Date Date Optional Calendar days, DD-MMM-YYYY. Set by the drop position. NEW “Due Date should be on or after Start Date.” 
 Search Alphanumeric Optional Matches Key or Title in the Unscheduled list. — 
### Rules to check
 6 Edit access can drag. View access reads the chart.
 Two people editing the same bar: both entries stay in History. The latest save shows on refresh.
 No dates and no sprint: the issue stays in the Unscheduled list.
 No dates but a sprint: a light bar spans the sprint.
 Due Date and Estimate but no Start Date: a dashed bar ends on the Due Date. Its length is 8 hours to 1 working day.
 The Unscheduled list stays searchable on large boards (for example 765 Backlog and 724 To Do issues).
 When it is done
The issue has its new dates. The bar shows them and History records the change. A scheduled issue leaves the Unscheduled list.

## Link issues and compare with a baseline
 Role Delivery Head 
 Goal dependency lines and a saved baseline on the Gantt 
 Benefit I can see what holds up work and how far we moved from the first plan 
### Simple Example se samjho: Yeh kyun chahiye?
 Maan lo: Client ko bola ki 30 Nov ko project deliver karenge.
 1. Day 1 (Freeze Plan): Sabhi tasks ki dates set karke "Save Baseline" (Agreed plan) daba diya — ye original promise freeze ho gaya.
 2. Dependencies & Critical Path: Backend API khatam hone par hi Frontend UI banegi (Finish-to-Start line). Agar blocker task delay hota hai, to dependency line RED ho jayegi (conflict warning), lekin koi bhi task auto-shift nahi hoga taaki developers ka calendar disturb na ho. "Critical path" button on karte hi saaf dikhta hai ki kaunsa task delay hone se poori project delivery 30 Nov se aage slip ho jayegi.
 3. Day 15 (Kaam Delay Hua): Developer beemar hua to task ko Gantt pe aage khiska ke 05 Dec kar diya. Asli Kaam: Chart pe ek faint grey bar purani date (30 Nov) par chipki rehti hai aur colored bar nayi date (05 Dec) par. Hover karte hi saaf dikhta hai: "Planned: 30-Nov | Actual: 05-Dec (Delay: 5 days)". Client aur management ko crystal-clear proof milta hai ki original commitment kya tha aur kitne din delay hua.
 Waise sach bolun Sir, to ye project manager ka sabse bada hathiyar hai audit aur client arguments me prove karne ke liye.
 Who uses it
 Delivery Head Project Manager Team Member 
 What it touches
 Link Issue Issue History Notification Settings 
 Needs
Edit access to link issues and save a baseline. Common rules apply. 
 [IMG] Dependency lines between linked issues. Click to enlarge [IMG] The chain of issues ends at the project End Date. Click to enlarge [IMG] Save baseline and Show baseline. The grey bar under each bar is the saved plan. Click to enlarge 
### Steps
 6 Go to Tasks → <project> → Issue List → <issue key> → Link Issue. Pick “Blocks” or “Is Blocked By”, pick the target issue, click “Link”. NEW History logs user name, link type and linked issue key.
 NEW Open the Gantt. A dependency line joins linked issues:
 Finish-to-start: ends at the blocked issue’s Start Date
 Start-to-start: joins two Start Dates
 Finish-to-finish: joins two Due Dates
 NEW If a blocked issue starts before its blocker ends, the line turns red and flags the scheduling conflict.
 NEW Click “Baseline” on the toolbar, enter a name (e.g. Agreed plan) and click “Save baseline”. The original commitment dates of every dated issue are frozen.
 NEW Drag a task forward to simulate a delay. A faint grey baseline bar stays stuck at the original dates underneath the current colored bar.
 NEW Point at the bar to see planned vs actual dates and slip: “Planned: 30-Nov-2026 | Actual: 05-Dec-2026 (Delay: 5 days)”. Toggle “Show baseline” to show or hide the saved grey bars.
### Fields
 2 Field Type Required Format Error message
 Link relationship Dropdown Optional Is Blocked By, Blocks, Is Cloned By, Is Duplicated By, Duplicates, Related To. NEW On the Gantt: start-to-start and finish-to-finish. — 
 Baseline name Alphanumeric Mandatory Free text, for example Agreed plan. NEW “Baseline name is required.” 
### Rules to check
 4 Existing link types are kept. Linked issues still show under Linked Issues on the panel.
 Deleting an issue removes it and its lines from the chart.
 The baseline keeps the first saved dates even after bars move: a faint grey bar stays stuck at the original dates under the moved bar and the hover card shows planned vs actual dates with delay in days.
 Saving a baseline adds no History entry and leaves work logs untouched.
 When it is done
All links show as lines with the right direction and colour (red on conflict). The first plan sits under today’s bars.

## Plan people on a Hire Base project
 Role Delivery Head 
 Goal developer rows, contract bands and a double-booking warning on a Hire Base Gantt 
 Benefit I can plan dedicated people across projects without clashes 
### Simple Example se samjho: Yeh kyun chahiye?
 Maan lo: Client ne Liam Brooks aur Sofia Reyes ko monthly dedicated hire kiya hai (Hire Base project) aur dono ka contract 28-Nov ko expire ho raha hai.
 1. Developer Contract Bands: Gantt kholte hi developers ke rows dikhte hain. Har developer ke naam ke aage uski contract duration ka blue band dikhta hai (e.g. 01-Nov to 28-Nov, 8 days left). Agar developer ke contract ke bahar task plan kiya to turant warning milti hai.
 2. Double-Booking Clash: Agar doosre project manager ne bhi Liam ko usi hafte kisi aur project me assign kar diya, to Liam ke row pe bold red ⚠️ Clashing [Resolve] button flashing shuru ho jayega. PM ko turant pata chal jata hai ki Liam over-allocated hai aur client clash pakad lega.
 Waise sach bolun Sir, to Hire Base me agar developer double-book ho gaya to client payment rok deta hai — isliye yeh clash warning company ka paisa bachati hai.
 Who uses it
 Delivery Head Project Manager 
 What it touches
 Resource Planner Work Log and Billing Fixed Cost Report Hourly Report Hirebase Report 
 Needs
View access. A Hire Base project with contract developers. Common rules apply.

## See all boards and all projects
 Role Project Manager 
 Goal one Gantt across every board of a project and Projects Timeline on the Dashboard 
 Benefit I can plan across boards and review all projects in one place 
### Simple Example se samjho: Yeh kyun chahiye?
 Maan lo: Delivery Head ya CEO ko review meeting me dekhna hai ki company ke 15 chal rahe projects kahan tak pahuche aur kaunsa project late chal raha hai.
 1. Purani Problem: Har project ke andar jao, tasks kholo, board badlo — 15 projects check karne me aadha ghanta lag jata tha aur overall company ka roadmap ek jagah nahi milta tha.
 2. Multi-Board View: Ek project ke andar Default Board aur Test Board dono ke issues ek hi Gantt me Board column badge ke sath merge hoke dikhte hain.
 3. Projects Timeline: Side navigation me Dashboard kholte hi Projects Timeline khulti hai. Ek hi calendar pe saare projects (Fixed Cost, Hourly, Hire Base) ek ke neeche ek rows me dikhte hain with unke start/end duration aur milestones. Ek glance me pata chal jata hai kaunsa project on track hai aur kaunsa red alert pe hai.
 Waise sach bolun Sir, to management level pe actual value yahi se aati hai jab poori company ka schedule ek hi screen pe roadmap ban ke dikhta hai.
 Who uses it
 Project Manager Delivery Head 
 What it touches
 No impact 
 Needs
View access to the projects and the Dashboard. Common rules apply. 
 [IMG] The project selector: one Gantt for the whole project. Click to enlarge 
### Steps
